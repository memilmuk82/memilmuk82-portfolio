# MILIM 포트폴리오 멀티에이전트 완성·검증 작업

## 역할과 목표

당신은 `/opt/apps/memilmuk82-portfolio`의 총괄 에이전트다. 반드시 멀티에이전트 기능을 사용해 독립적인 하위 역할을 병렬로 운영하고, 지금까지 사용자와 합의한 실제 요구사항이 소스·화면·테스트·문서에 일관되게 반영됐는지 감사한다. 누락이나 회귀가 있으면 현재 디자인 시스템과 코드 구조 안에서 직접 수정하고 다시 검증한다.

단순 보고로 끝내지 않는다. 안전하고 작업 범위 안에서 고칠 수 있는 문제는 고친 뒤 검증해야 한다. 다만 이미 충족된 요구를 이유 없이 재작성하거나 디자인을 새로 만들지 않는다.

## 사용자 요구사항 — 변경 불가 기준

1. 기준 모집단은 `/opt/apps` 바로 아래의 독립 Git 저장소 56개다.
2. 포트폴리오 프로젝트 인벤토리의 최종 분류는 다음과 같다.
   - 서브도메인 웹앱 9개
     - PostgreSQL 3개
     - SQLite 5개
     - 무DB 1개
   - 정적 사이트 7개
   - 소스·프로젝트 소개 28개
   - 비공개·제외 12개
   - 합계 56개, 누락 0, 중복 0
3. `noom`은 데이터베이스를 추가하지 않는 무DB 웹앱이다.
   - Node.js·Socket.IO·Docker 기반
   - 서브도메인 웹앱 분류
   - 실제 DB를 만들거나 PostgreSQL/SQLite 의존성을 억지로 추가하지 않는다.
4. `curriculum-subject-overlap-check`는 비공개다.
   - 외부 저장소·사이트·산출물 링크를 공개 화면에 제공하지 않는다.
   - 비공개·제외 분류에 포함한다.
   - 원문 교육과정 자료를 복제하거나 공개하지 않는다.
5. 2020년부터 2026년까지 가르치는 내용이 바뀌어 온 흐름을 포트폴리오에 보여 준다.
   - 2020—2021: 프로그래밍과 웹의 기초
   - 2022—2023: 서버·API·데이터로 확장
   - 2024—2025: 서비스와 에듀테크
   - 2026: AI 활용에서 설계·검증으로
   - 근거 없는 학교명, 학생 성과 수치, 경력 수치, 연도별 세부 사건은 만들지 않는다.
6. 홈페이지는 56개 프로젝트와 9·7·28 분류를 즉시 이해할 수 있어야 한다.
7. 프로젝트 화면은 56개 전부를 검색·연결 방식으로 필터링할 수 있어야 한다.
8. 확인된 운영 URL, GitHub 저장소와 산출물 링크만 용도가 명시된 HTTPS 필드로 제공한다.
9. 비공개·제외 항목은 링크를 제공하지 않는다.
10. 현재의 종이색·잉크·코발트·시트론 팔레트, 열린 편집형 행, 얇은 구분선, 모바일 단일 열 시스템을 유지한다.

## 멀티에이전트 구성

가능한 동시성 안에서 다음 네 역할을 병렬로 시작한다. 하위 에이전트는 또 다른 하위 에이전트를 만들지 않는다.

### A. 인벤토리·콘텐츠 감사

- 56개 이름, slug 중복, 분류 수량과 공개 링크를 검증한다.
- `noom`과 비공개 교육과정 프로젝트의 최종 결정을 확인한다.
- 민감한 로컬 경로, 자격증명, 내부 메모가 사용자 화면이나 공개 JSON에 새로 노출되지 않았는지 확인한다.
- 원칙적으로 읽기 전용으로 조사하고, 발견 사항과 정확한 수정 제안을 총괄에게 전달한다.

### B. 화면·반응형 감사

- 홈·프로젝트·활동·소개 화면의 콘텐츠 계층, 긴 이름, 필터, 링크, 2020—2026 타임라인을 검사한다.
- 데스크톱 1440×1100, 모바일 390×844를 우선하며 360px 폭도 고려한다.
- 가로 오버플로, 잘린 콘텐츠, 브라우저 기본 제어 타이포그래피, 빈 링크, 불필요한 카드화를 찾는다.
- 기존 디자인 콘셉트와 최신 스크린샷을 비교하되 사용자 콘텐츠가 시각 예시보다 우선이다.

### C. 기능·보안·회귀 검증

- JSON 파싱, Ruff, pytest, Tailwind 빌드, 서버 렌더링 필터를 검증한다.
- 기대값은 전체 56, 서브도메인 9, 정적 7, 소스 28, 비공개·제외 12다.
- `noom`은 서브도메인 필터에 나타나야 하고, 비공개 교육과정 항목에는 외부 링크가 없어야 한다.
- 외부 링크의 HTTPS와 `noopener noreferrer`, 오류 페이지와 보안 헤더 회귀를 확인한다.
- 네트워크나 소켓 권한으로 브라우저 실행이 막히면 Flask 테스트 클라이언트와 정적 검증으로 대체하고 제약을 기록한다.

### D. 문서·변경 보존 감사

- README, 상태, QA, 시각 원장의 현재 계약이 9·7·28·12 및 교육 변화와 일치하는지 확인한다.
- 기존 워크트리 변경을 사용자 소유로 간주한다.
- 배포 관련 기존 변경을 되돌리거나 덮어쓰지 않는다.
- 과거 문서가 역사 기록이라면 현재 적용 상태와 구분되도록 명확히 한다.

## 총괄 통합 규칙

1. 에이전트 결과를 비교하고 사실 충돌은 현재 코드와 테스트 증거로 해결한다.
2. 같은 파일을 여러 에이전트가 동시에 수정하지 않게 한다. 하위 역할은 우선 조사·보고하고 총괄이 통합 수정한다.
3. 편집은 `apply_patch`를 우선한다.
4. 사용자 변경과 무관한 파일을 정리하거나 포맷하지 않는다.
5. `git reset --hard`, `git checkout --`, 광범위 삭제를 사용하지 않는다.
6. Git commit, push, PR, DNS, Nginx 적용, 인증서 발급, 외부 서비스 배포를 수행하지 않는다.
7. `/opt/apps`의 다른 프로젝트는 읽기 전용 조사 대상으로만 사용하고 수정하지 않는다.
8. 비밀값이나 개인정보를 로그·보고서에 복사하지 않는다.

## 필수 검증

가능한 검증을 모두 실행한다.

```bash
.venv/bin/python -m json.tool app/content/project_inventory.json
.venv/bin/ruff check app tests
.venv/bin/ruff format --check app tests
.venv/bin/python -m pytest -q
npm run css:build
```

추가로 다음 불변 조건을 검증한다.

- 인벤토리 항목 수 56
- slug 중복 0
- 분류 수량 `9, 7, 28, 12`
- `noom.group == "subdomain"`
- `noom.stack`에 무DB 의미가 명시됨
- 비공개 교육과정 항목에 `repository_url`, `live_url`, `artifact_url` 없음
- 활동 화면에 네 시기와 2020—2026 변화 설명 존재
- 서버 기반 필터가 JavaScript 없이도 동작
- 모바일과 데스크톱에 가로 오버플로 없음(브라우저 실행 가능 시)

## 실행 상태와 결과 기록

실행 시 프롬프트 끝에 제공되는 `STATE_FILE`을 작업 단계마다 갱신한다.

- 시작
- 하위 에이전트 배정
- 조사 결과 수집
- 통합 수정
- 검증
- 완료 또는 명시적 제약

최종 응답에는 다음을 포함한다.

- 실제 수정한 내용
- 유지 확인한 사용자 요구사항
- 실행한 검사와 결과
- 브라우저 검수 방법 또는 대체 검증 이유
- 남은 문제와 외부 작업이 필요한 항목
- 기존 사용자 변경을 보존했는지 여부

모든 안전한 범위의 수정과 검증이 끝나기 전에는 완료로 선언하지 않는다.
