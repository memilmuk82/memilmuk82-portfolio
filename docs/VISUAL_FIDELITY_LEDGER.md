## 초기 mismatch와 수정

### M-01 — 푸터 다음 현재 페이지명 노출 — 수정 완료

초기 구현은 `page_name` Jinja 블록이 `</html>` 뒤에서 출력되어 캡처 맨 아래에 `홈`, `프로젝트`, `활동`, `소개`가 보였다. 콘셉트에는 없는 요소이며 페이지 종료 리듬을 훼손했다.

- 수정: 문서 끝의 블록 출력을 제거했다.
- 재검증: 다섯 데스크톱과 다섯 모바일 페이지의 `footer.nextSibling` 가시 텍스트가 모두 비어 있다.
- 최종 캡처: 푸터가 마지막 가시 표면으로 끝난다.

### M-02 — 모바일 오버레이의 포커스 이탈 — 수정 완료

시각적 메뉴는 콘셉트에 가까웠지만, 초기에는 마지막 링크 다음 Tab이 가려진 본문으로 빠져 화면 상태와 포커스 상태가 어긋났다.

- 수정: 토글과 네 메뉴 링크 사이에 양방향 포커스 순환을 구현했다.
- 재검증: 첫 링크 `Shift+Tab` → 토글, 토글 `Shift+Tab` → 마지막 링크, 마지막 링크 `Tab` → 토글, `Escape` → 닫힘·토글 복귀.
- 시각 결과: `mobile-menu-open.png`의 오버레이와 포커스 윤곽이 상태를 정확히 표현한다.

### M-03 — 파비콘 부재 — 수정 완료

초기 브라우저 캡처 과정에서 `/favicon.ico`가 404였다. 자체 SVG 파비콘과 호환 라우트를 추가한 뒤 모든 페이지가 동일 출처 파비콘을 200으로 로드한다.

## 의도적 차이와 근거

### D-01 — 콘셉트의 미검증 프로젝트·기술·수치를 사용하지 않음

프로젝트 콘셉트에는 5개 프로젝트, 보류 대상, 잘못된 FastAPI·MySQL·React 표기, 역할·운영 상태가 들어 있다. 최종 구현은 콘텐츠 검증이 우선이므로 승인된 네 설명만 표시하고 Flask·PostgreSQL 등 확인된 기술로 교정했다. 이는 시각 충실도 저하가 아니라 공개 안전성 향상이다.

상세 콘셉트의 대상 사용자, 교내 시범 운영, 테스트 결과 등 확인되지 않은 설명도 복사하지 않았다. 대신 `공개 범위`, `다음 개선`을 넣어 정보 밀도와 2열 리듬을 유지했다.

### D-02 — 모바일 접이식 필터 대신 항상 보이는 네이티브 컨트롤

콘셉트는 체크박스형 필터 패널을 제안하지만, 최종 구현은 검색 입력과 주제·상태 `select`를 항상 보이게 했다. JavaScript가 없어도 GET 폼이 동작하고 44px 이상 조작 영역을 보장하는 점진적 향상을 우선한 결정이다.

### D-03 — 블루프린트 아이콘 단순화

콘셉트의 세밀한 선형 도식 대신 CSS 원형 노드와 문자 기호를 사용했다. 경로·계층·강조색은 보존하고 외부 아이콘 의존성을 없앴다. Firefox에서는 `⌘`가 단순 기호처럼 보일 수 있어 향후 자체 SVG 세트로 정교화할 수 있으나, 장식은 `aria-hidden`이며 현재 이해·탐색을 막지 않아 비차단 차이로 승인한다.

### D-04 — 홈 영웅의 세로 여백과 줄바꿈

최종 1440px 캡처는 콘셉트보다 영웅의 세로 여백이 크고 제목이 3행으로 보인다. 폰트 파일을 외부에서 가져오지 않고 시스템 한국어 폴백을 사용하는 조건에서 생긴 조판 차이다. 첫 화면에서 제목, 설명, 두 CTA와 블루프린트가 모두 보이고 계층이 유지되어 승인한다.

### D-05 — 저작권 연도·이메일·미검증 외부 링크 제외

콘셉트의 임의 연도, 이메일, 추가 외부 아이콘은 근거로 사용하지 않았다. 최종 푸터는 상시 탐색과 검증된 프로필 연결만 제공한다.

## 최종 agency sign-off

**승인한다.** 최종 구현은 콘셉트의 핵심인 한국어 편집형 계층, 중립·코발트 팔레트, 열린 행, 블루프린트 경로, 넓은 여백, 모바일 재배치를 일관되게 구현했다. 초기 가시 결함은 최종 캡처에서 해결됐고, 1440×1100·390×844·360×800에서 클리핑과 가로 오버플로가 없다.

문서화된 차이는 검증되지 않은 콘텐츠 배제, 서버 폼 우선, 시스템 폰트 폴백, 장식 아이콘 단순화에서 비롯된다. 이 차이는 사용자 정보 계층과 핵심 탐색을 훼손하지 않으므로 출시 준비를 막지 않는다. 데스크톱 블루프린트의 추가 마이크로카피는 승인 콘셉트 보존을 위한 카피 잠금 예외로 명시한다.

## 남은 환경 제약

- Flask/Gunicorn TCP 바인딩은 샌드박스의 `PermissionError: [Errno 1] Operation not permitted`로 실행하지 못했다.
- Chromium은 프로세스 샌드박스 제약으로 기동하지 못해 Playwright Firefox로 검수했다.
- 실제 Chrome, Safari, 운영 Nginx, TLS, 외부 네트워크 폰트·성능은 검수하지 않았다. 앱은 외부 CDN·폰트 요청을 만들지 않는다.
- `route.fulfill` 기반 캡처이므로 LCP·실제 네트워크 타이밍에 대한 sign-off는 포함하지 않는다.
- Browser 플러그인을 설치한 환경에서는 in-app DOM snapshot, 콘솔, 스크린샷과 상호작용을 같은 네이티브 뷰포트로 한 번 더 확인할 수 있다.
