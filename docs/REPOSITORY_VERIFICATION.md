# 저장소·프로젝트 공개 검증

> 현재 적용 상태(2026-07-18): 이 문서의 초기 `default deny` 결정으로 상세 사례는 네 개만 남았지만, 그 결정을 56개 프로젝트 목록 전체에 적용한 것은 사용자 요구와 달랐다. 현재 앱은 `app/content/project_inventory.json`에 독립 저장소 56개 전부를 9·7·28·12로 분류한다. `noom`은 무DB 서브도메인 웹앱, `curriculum-subject-overlap-check`는 링크를 제공하지 않는 비공개 항목이다. 아래의 네 후보 제한과 링크 보류 내용은 최초 구현 당시의 판단 기록이며 현재 프로젝트 목록 계약이 아니다.

검증일: 2026-07-18 (Asia/Seoul)
담당 역할: 저장소·프로젝트 검증 에이전트
결론: 기존 정적 초안의 공개 JSON은 그대로 복사하지 않는다. 아래 허용 범위만 새 콘텐츠 파일에 다시 작성하고, 근거가 부족한 항목은 기본적으로 공개하지 않는다.

## 1. 조사 범위와 보존 원칙

다음 읽기 전용 자료를 대조했다.

- 포트폴리오 제작 제안서
- 저장소 분류 요약, 수동 확인 로그, 전체 실행 로그
- 기존 Vite/TypeScript 초안의 공개 후보 JSON, 내부 검토용 원본 JSON, 화면 소스, 디자인 콘셉트, QA 스크립트와 상태 문서
- 공개 후보 5개 저장소의 README, 의존성 선언, 핵심 앱 구조와 현재 추적 파일명

새 프로젝트 루트에는 `AGENTS.md`가 없었고 `.agents/`, `.codex/`는 비어 있었다. 시작 시점의 `.git/`도 비어 있어 유효한 Git 저장소가 아니었다. 이 역할에서는 참고 프로젝트와 Git 설정을 수정하지 않았다.

분류 자료의 기술적 후보 판정은 곧바로 포트폴리오 공개 승인을 뜻하지 않는다. 내부 모집단 수와 분류 집계는 공개 산출물에 옮기지 않았다.

공개 콘텐츠는 **기본 거부(default deny)** 로 다룬다. 아래에 명시적으로 허용되지 않은 저장소명, 내부 분류, 검토 메모, 로컬 경로는 새 JSON과 사용자 화면에 넣지 않는다. 특히 기존 `projects.source.json`은 내부 보류 사유를 포함하므로 복사하거나 Git에 추가하지 않는다.

## 2. 판정 기준

프로젝트 설명 공개와 외부 링크 공개를 분리해 판정했다.

1. 현재 코드나 프로젝트 문서에서 목적·스택·산출물을 직접 확인할 수 있어야 한다.
2. 역할, 결과, 운영 상태, 수치가 문서나 코드로 검증되지 않으면 삭제하거나 `TODO(owner)`로 남긴다.
3. 공개 설명이 가능해도 데모·저장소·외부 산출물 링크는 현재 응답, 소유권, 공유 범위, 민감정보와 권리 검토가 별도로 끝나야 한다.
4. 학생·상담·계정·예약·채팅·업로드·OAuth 데이터는 합성 자료 외에는 화면과 콘텐츠에 사용하지 않는다.
5. 라이선스가 확인되지 않은 저장소에서 코드, 문구, 이미지나 슬라이드 자산을 복제하지 않는다. 프로젝트를 사실대로 요약하고 외부 링크를 제공하는 것과 자산을 재사용하는 것은 다른 승인이다.
6. 현재 트리 검사만으로 Git 과거 이력의 비밀값 부재를 증명하지 않는다. 과거 노출 정황이 있는 저장소는 회전과 이력 검토가 끝날 때까지 링크를 보류한다.

## 4. 기존 공개 JSON의 신뢰 한계

기존 정적 초안은 공개 후보 5개에 네 개 검토 불리언을 모두 `true`로 두고 빌드했다. 그러나 검증 스크립트는 불리언 값과 필수 필드 존재 여부만 검사한다. 다음을 증명하지 않는다.

- 비밀값 회전 또는 Git 전체 이력 검사 완료
- 외부 URL의 실제 HTTP 응답, 소유권, 최종 리디렉션과 공유 범위
- 이미지·교육자료·슬라이드의 출처 및 재배포 허가
- 운영 데이터와 합성 데모 데이터의 실제 격리
- 역할·성과·운영 상태를 뒷받침하는 독립 증거

링크 검사도 HTTPS 문법과 URL 내 자격 증명 부재만 확인했다. 따라서 `public: true`, `securityReviewed: true`, `rightsReviewed: true`, `linksReviewed: true`를 새 데이터에 기계적으로 계승하지 않는다.

기존 배포 번들과 공개 소스에 대해 로컬 경로, 분류 파일명, `file://`, `localhost`, 대표적인 개인키/클라우드 키 패턴을 다시 검색했다. 실제 공개 데이터에서는 발견되지 않았고, 금지 문자열 자체는 감사 스크립트 정의에만 있었다. 이는 긍정적이지만 완전한 비밀 탐지 결과는 아니다.

## 5. 민감정보·보안·권리 위험

### 비밀값

- 보안 검토 보류 후보는 추적된 환경 파일 때문에 위험도가 **높음**이다. 실제 이름과 값은 이 문서나 새 저장소에 옮기지 않았다.
- `junior-college-admission`과 `gpt-manager`는 추적 파일명 기준 `.env.example`만 확인했지만, 설정 참조가 많으므로 정식 비밀 탐지와 이력 검사가 여전히 필요하다.
- 외부 API를 사용하는 지도·OpenAPI·AI 실험 항목은 분류 자료에 과거 키 회전 또는 이력 점검 필요가 반복 기록되어 있다. 허용 목록 밖에서는 이름과 링크도 공개하지 않는다.

### 개인정보와 내부 운영 정보

- 입시 상담: 실제 학생 자료, 학교별 내부 규칙, 업로드/OCR 파생물, 운영 DB와 캡처를 사용하지 않는다.
- 계정 운영: 사용자 계정, 예약, 사용 기록, 관리자 보고, 조직 정보와 운영 DB를 사용하지 않는다.
- 교육자료: 기관 계정, 교사·학생 화면, 조직도, 설문 결과, 캡처 속 개인정보를 제거한다.
- SNS·채팅: 사용자·OAuth·게시물·채팅 기록과 실제 도메인 비밀을 사용하지 않는다.
- 새 사용자 화면에 로컬 절대 경로, 내부 분류 수, 검토 점수, 비공개 저장소 목록을 표시하지 않는다.

### 라이선스와 자산 권리

- 보안 검토 보류 후보에 재사용 허용 취지의 라이선스가 있더라도 비밀값 위험이 우선하므로 공개 보류를 해제하지 않는다.
- 나머지 MVP 설명 후보 네 저장소는 루트 라이선스가 없었다. 자체 요약 외 재사용은 금지한다.
- 디자인 콘셉트 이미지는 새 UI 구현의 비교 자료로만 사용한다. 배경 이미지나 페이지 캡처로 배포하지 않는다.
- Google Slides, Canva, 로고, 외부 작품, 지도·학교·교육과정 데이터는 각 출처와 공유 권리가 확인되기 전 복제하지 않는다.

## 6. 링크 정책

외부 링크는 새 콘텐츠 데이터에서 선택 필드로 둔다. 링크가 없는 상태에서도 상세 페이지가 완전한 서버 렌더링 콘텐츠를 제공해야 한다.

- 허용 프로토콜은 `https`뿐이다.
- 사용자명·비밀번호·토큰·쿼리 기반 비밀값이 들어간 URL은 거부한다.
- 템플릿은 새 탭 링크에 `rel="noopener noreferrer"`를 강제한다.
- GitHub 링크는 저장소 공개 여부와 소유권을 확인하고, 데모·Slides 링크는 실제 응답과 공유 범위를 확인한다.
- 마지막 확인일은 링크별로 기록한다. 로컬에서 네트워크 검증을 못 했으면 `미확인`으로 남기고 사용자 화면에 링크를 내보내지 않는다.
- 외부 앱을 iframe으로 삽입하지 않는다.

## 7. Vite 초안에서 보존할 것과 대체할 것

### 보존

- 종이색 배경, 짙은 잉크색, 코발트와 제한적인 시트론으로 구성된 색상 방향
- 카드 격자 대신 열린 프로젝트 행, 편집형 섹션, 전체 폭 밴드와 얇은 구분선을 쓰는 레이아웃
- `문제 → 판단 → 결과` 정보 흐름과 한국어 중심의 절제된 카피
- 760px 이하 재배치, 20px 모바일 여백, 44px 이상 조작 영역, skip link, `focus-visible`, `prefers-reduced-motion`, `aria-live` 결과 수
- 검색·주제·상태 필터의 조합 동작, 외부 링크 안전 속성, 가로 오버플로·모바일 메뉴·키보드 QA 시나리오
- 홈·프로젝트·상세·소개·모바일 섹션 단위 콘셉트 이미지는 시각 참고 자료로만 보존

### Flask 전환에서 대체

- Vite/TypeScript SPA와 해시 라우팅 → Flask 앱 팩토리, 기능별 Blueprint, Jinja 템플릿 상속과 실제 URL
- 클라이언트에서 전체 화면을 생성하는 `main.ts` → 의미론적 서버 렌더링 HTML과 필요한 필터·메뉴만 Vanilla JavaScript로 점진적 향상
- 원본 JSON에서 공개 JSON을 생성하는 Node 스크립트 → 새로 작성한 최소 공개 JSON과 Python 스키마 검증
- Vite 전용 소스 계약 → pytest 라우트·콘텐츠·헤더·링크 검사와 브라우저 QA
- 기존 `dist/`, `node_modules/`, 잠금/캐시 산출물 → 복사하지 않음
- 기존 이미지 시안을 런타임 자산으로 사용 → 금지; 실제 HTML/CSS로 재구현

## 8. 빌더 전달 사항

1. 새 공개 데이터는 이 문서의 네 설명 후보만 별도 파일에 손으로 다시 작성한다. 보안 검토 보류 후보는 초기 데이터에서 제외한다.
2. 네 후보도 외부 링크는 검증 완료 전 `null` 또는 필드 생략으로 둔다. 링크가 없어도 카드·상세·필터가 동작해야 한다.
3. `junior-college-admission` 스택은 Flask로 기록한다. 테스트 수, 이용자 수, 성과율, 운영 성공 같은 수치는 넣지 않는다.
4. `whalespace-training`은 60장 산출물과 검수 기록을 설명할 수 있지만, Slides URL은 공유·권리 확인 전 노출하지 않는다.
5. 프로젝트 상세의 `결과`는 “구현·문서·검증 절차를 제공한다”처럼 확인 가능한 산출물로 표현한다. 외부 효과나 고객 성과를 추정하지 않는다.
6. 활동 페이지에는 프로젝트명이 아니라 `Flask 웹앱`, `교육자료 제작`, `자동화·검증`, `인프라·배포 준비`처럼 검증된 주제 축을 우선 사용한다.
7. 데이터 스키마에는 최소 `public`, `security_reviewed`, `privacy_reviewed`, `rights_reviewed`, `links_reviewed`, `last_verified`를 두되, 검증 증거 없이 값을 참으로 만들지 않는다.
8. 테스트에 금지 문자열, 비공개 항목 slug, 로컬 경로, 내부 메모 필드, 외부 링크 `rel`과 허용 프로토콜 검사를 포함한다.

## 9. 이번 역할의 미수행 항목

- 외부 URL HTTP 응답, GitHub 공개/비공개 상태와 소유권은 네트워크를 사용해 재검증하지 않았다.
- Git 전체 이력에 대한 전용 비밀 탐지 도구 검사는 수행하지 않았다.
- 실제 데모 계정 로그인, 운영 DB, 학생·사용자 데이터, Google Slides 공유 설정은 열람하지 않았다.
- 코드·콘텐츠·Git 설정·참고 프로젝트는 수정하지 않았다.

이 미수행 항목은 공개 승인을 추정해 채우지 않는다. 빌더와 최종 검수 역할은 로컬 앱 구현을 계속하되, 외부 링크는 증거가 생길 때만 활성화해야 한다.
